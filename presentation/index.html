The Motivation

Monolithic Chatbots vs. Multi-Agent Teams

Most coding bots try to do everything at once — leading to hallucinations, broken builds, and zero adversarial review.

❌ Traditional Single Chatbot

• Assumes all roles: planner, coder, and self-reviewer.
• Blindly trusts its own code without independent validation.
• Commits or pushes code without human oversight.
• Isolated to one directory; lacks live team coordination.

✅ Our Multi-Agent Switch Workflow

• Strict Division of Labor: Codex scopes, Cursor codes, OpenCode audits.
• Adversarial QA: OpenCode runs tests & linters independently.
• Human Governance: Explicit approval gate before git commit/PR.
• Switch Backbone: Coordinates task state & Telegram mirroring.

Team Organization

Specialized Agent Roles & Responsibilities

Each agent has bounded responsibilities enforced by LangGraph state routing.

👑 Codex — Lead

• Receives Telegram requests.
• Classifies: Bug, Feature, Refactor.
• Scopes implementation plan.
• Relays QA findings & nudges.
• Compiles final summary report.

💻 Cursor — Developer

• Inspects target repository stack.
• Generates real code (never READMEs).
• Implements React/TS or Python features.
• Integrates components into entry points.
• Generates unified code diffs.

🛡️ OpenCode — QA & Review

• Reviews diff independently.
• Executes `pytest` & boundary suites.
• Runs `oxlint` & AST compilation.
• Triggers self-correcting loops.
• Issues PASS or FAIL verdicts.

The 7-Stage Engineering Pipeline

How human developer requests transform into verified production code.

1-2
Intake & Analysis (Codex)

Telegram message intake, task classification, requirement scoping, and task ID generation.

3-4
Investigation & Real Code Implementation (Cursor)

Detects stack (React/Vite/TS or Python), writes functional components, and generates unified diff.

5
Adversarial QA & Correction Loop (OpenCode)

Runs automated tests. If failed, Codex routes critique back to Cursor (up to 3 auto-correction cycles).

6-7
Human Approval Gate & Git PR Generation

Developer inspects `/diff` and approves; Git creates isolated branch, commits, and opens PR.

Enterprise Governance

Safety Safeguards & Multi-Project Flexibility

Built for real developer workflows with safety boundaries and multi-repo support.

🔒 Production Safety Controls

• Human Gate: Zero automatic pushes or unreviewed PR merges.
• Path Confinement: Validates all writes strictly within project root.
• Cycle Limits: Correction loops capped at 3 attempts to prevent infinite recursion.
• Credential Isolation: Tokens and keys never mirrored to chat feeds.

📁 Multi-Project Architecture

• Live Project Switching: Switch projects via `/use ` in Telegram.
• File Tree & Reader: `/files` and `/read ` directly in chat.
• Multi-Language QA: Tested on React 19 / TypeScript and Python.
• Safe Undo: Instant `/undo` revert for accidental changes.
